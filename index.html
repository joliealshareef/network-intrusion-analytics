Network Intrusion Analytics

Catch the attacks nobody trained for.

I trained machine learning models on 125,973 network connections, then tested them on 22,544 more, including 17 attack types the models had never seen.

The data

The test set doesn't look like the training set.

NSL-KDD splits traffic into normal connections and four attack families. The test set is much heavier on remote-access attacks, which is what makes it hard.

Share of each family

Percent of connections in each split

Four kinds of attack

DoS: flooding a service until it stops responding (neptune, smurf)
Probe: scanning to map hosts and open ports (nmap, satan)
R2L: remote-to-local, gaining access from outside, like password guessing
U2R: user-to-root, escalating a normal account to admin

The models

Four ways to flag an attack.

Two supervised models learn from labeled examples. One anomaly detector learns only what normal looks like. The layered approach raises an alert when either the Random Forest or the anomaly detector does.

Method

How it was built.

1

Load and label

Read KDDTrain+ and KDDTest+, then mapped all 39 attack names to the four standard families (DoS, Probe, R2L, U2R).

2

Encode features

One-hot encoded protocol, service and TCP flag, which took 41 raw features to 121 columns. Dropped one constant column. Aligned test columns to training columns.

3

Train three models

Logistic Regression on scaled features as a baseline. Random Forest with 200 trees. Isolation Forest fitted only on normal training traffic, with 10% contamination.

4

Layer them

Raised an alert when either the Random Forest or the Isolation Forest flagged a connection, the way a SOC runs signature and anomaly detection side by side.

5

Evaluate on held-out data

Measured accuracy, precision, recall, false alarm rate and ROC AUC on the official test set, then split results by family and by seen versus unseen attack type.
